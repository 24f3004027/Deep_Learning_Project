
### Key Components:
*   **Vocabulary Mapping**: Custom vocabulary of size 3,091 words built from the training corpus. Unknown words are mapped to a stable `<UNK>` embedding.
*   **Recurrent Processing**: A bidirectional GRU layer (hidden state size 128) processes word tokens, yielding sequence context vectors.
*   **Self-Attention Pooling**: An attention layer assigns weights to each token hidden state:
    \[ \alpha_t = \text{softmax}(\mathbf{w}_a^\top \tanh(\mathbf{W}_h \mathbf{h}_t + \mathbf{b}_h)) \]
    This pools the 128 token vectors into a single 256-dimensional sentence vector based on contextual importance.
*   **Output Projection**: Projects the pooled vector to a single logit per choice.

To leverage transfer learning, we fine-tune a pre-trained `distilbert-base-uncased` model:

*   **Encoder**: 6 transformer layers with 12 attention heads.
*   **Pooling**: Extracted using the classification token `[CLS]` representation.
*   **Fine-Tuning Strategy**: Full parameter update with a low learning rate (2e-5) using AdamW with weight decay (0.01) to regularize transformer weights.

## 4. Model 3: DeBERTa-v3 + LoRA PEFT + RAG (Choice Model)
Our final model utilizes a hybrid Retrieval-Augmented Generation (RAG) and parameter-efficient fine-tuning (PEFT) framework:

### 1. Vector Database (RAG)
We fit a local TF-IDF Vector Database on the correct options of the training set. For each test prompt, we query the DB to retrieve the top 2 most semantically related facts. These facts are prepended as context to the prompt:
`context: [Fact 1] [Fact 2] question: [Prompt]`

### 2. Parameter-Efficient Fine-Tuning (LoRA)
We load the pre-trained `microsoft/deberta-v3-small` model and wrap it with LoRA adapters:
*   **Rank (\( r \))**: 8
*   **Alpha (\( \alpha \))**: 16
*   **Target Modules**: `query_proj`, `value_proj` (queries and values in attention blocks).
*   **Task Type**: Sequence Classification (`SEQ_CLS`).
This reduces the number of trainable parameters to **295,681**, allowing fast convergence and preventing overfitting on the small dataset.

---

## 5. Blending & Ensembling Pipeline
The final predictions are generated by averaging predictions across all pipelines:
\[ P_{\text{final}} = w_1 \cdot P_{\text{Scratch}} + w_2 \cdot P_{\text{DistilBERT}} + w_3 \cdot P_{\text{DeBERTa-LoRA}} \]
Where the weights are optimized to:
*   \( w_1 = 0.20 \)
*   \( w_2 = 0.40 \)
*   \( w_3 = 0.40 \)
The final probabilities are sorted to output the top 3 characters (e.g., `C A B`) in descending order.
